  kind TEXT DEFAULT 'patterns'       -- one kind only for now, keep the column for later kinds

  source_url TEXT                     -- optional link to the original pattern / inspiration (opened with rel="nofollow")

4. THE PROMPT GENERATOR  buildPrompts(title, info, n)
---------------------------------------------------------------------
Pure function, no AI API needed (rules-based). Output = n blocks "## Shot name\n<prompt>". Also export it so
a CLI can call it.

EVERY prompt starts with:
  "Use the attached photo as the reference for the crochet project: keep exactly the same piece — the same
  stitch pattern and texture, the same yarn colours in the same places, the same shape, size proportions and
  details (buttons, tassels, borders, faces). Do not change the design, do not add colours or motifs that are
  not in the photo. Only the photography changes: "
EVERY prompt ends with:
  "Realistic photo, natural handmade look with visible stitches and soft yarn fibres. No people's faces, no
  text, no logos, no watermark."
(No image size in the prompt — the editor sets the ratio in Flow.)

Read from the title + info: the project TYPE (from the title first; the info mentions everything, so it is
only a fallback), the yarn colours, the yarn weight, the hook size, the materials list.
Types and their styling (surface / props / texture / "in use" scene):
  amigurumi  (amigurumi, plush, toy, doll, bear, bunny, animal, keychain)
             → light wooden shelf or kids' room, a few wooden toys; texture: tight single crochet, safety eyes,
               embroidered details; in use: sitting on a child's bed pillows
  blanket    (blanket, afghan, throw, baby blanket, granny square blanket)
             → a sofa or bed with neutral linen; texture: the stitch pattern and border; in use: draped over an
               armchair or folded at the foot of a bed
  wearable   (sweater, cardigan, top, vest, hat, beanie, scarf, cowl, shawl, socks, mittens)
             → flat on a bed or on a wooden hanger / mannequin form; texture: ribbing, drape; in use: on a
               mannequin or hanging by a sunny window (no faces)
  bag        (bag, tote, purse, market bag, clutch)
             → a café table or a doorway hook, sunglasses, a book; texture: the mesh / tapestry stitch;
               in use: hanging from a chair with a few items inside
  home       (pillow, cushion, basket, coaster, rug, placemat, plant hanger, wall hanging, garland)
             → styled shelf / coffee table, a plant, a candle; texture: the stitch close-up; in use: in a cosy
               living room
  baby       (baby, booties, bib, lovey, rattle)
             → a nursery: soft white bedding, a wooden rattle; in use: in a crib (no baby)
  seasonal   (christmas, ornament, halloween, pumpkin, easter, valentine, heart, flower, snowflake)
             → a seasonal table or tree with matching props
  square     (granny square, motif, square, hexagon, block)
             → a flat lay of several identical squares on wood
  other      → a light wooden table with a linen cloth and a ball of the same yarn

SHOT LIST (in this order; take the first n, n = 5..10). Image 1 = hero of the article.
  1  Hero styled         the finished piece as the clear subject on {surface}, soft natural window light,
                         a few {props} out of focus behind it, 3/4 angle.
  2  Flat lay + tools    overhead flat-lay: the piece in the centre with balls of the same yarn colours, the
                         crochet hook ({hook} if known), scissors, stitch markers and a yarn needle around it.
  3  Stitch close-up     macro close-up of the stitches — {texture} — shallow depth of field, sharp front edge.
  4  In use / lifestyle  {in use scene}, wide 3/4 view, warm afternoon light.
  5  Materials spread    the materials only, before starting: {yarn colours} yarn balls, the hook, notions,
                         neatly laid out, with the finished piece partly visible at one edge.
  6  Work in progress    the piece half-finished with the hook still in the last loop and the working yarn
                         attached, on {surface}; same colours and stitch.
  7  Detail             a detail of the finishing: border, seam, buttons, tassels, embroidered face — the most
                         distinctive detail of this project.
  8  Cosy scene          the piece in a cosy home scene with a mug of tea and a book, golden light.
  9  Pinterest vertical  tall composition, the piece in the lower two thirds, soft empty space in the top third
                         (for a title added later), bright and airy.
  10 Bright & airy       minimal shot on a white surface with plenty of negative space, soft diffused daylight.
The admin can edit any prompt before the editor starts.

6. SOCIAL POSTS BOARD
---------------------------------------------------------------------
Tables (create if missing):
  social_articles (slug PRIMARY KEY, indexed INTEGER DEFAULT 0, indexed_at, notes, updated_at)
  social_cards (slug, n, PRIMARY KEY(slug, n),          -- n = the article image number, 1 = hero
     fb_image, pin_image,                               -- paths of the rendered images
     fb_caption, fb_comment, pin_title, pin_desc, label,
     pin_topics, pin_board, template,
     fb_posted_at, pin_posted_at, fb_log TEXT '[]', pin_log TEXT '[]',     -- every post date, newest first
     pin_bulk_at, pin_bulk_date, pin_bulk_file,                             -- Pinterest bulk upload
     bad_at, bad_note, bad_by, updated_at)
Add a column social_template to the articles table (editable in the article editor; the prep card's template is
copied to it when the article is published).

A) BOARD PAGE: one row per published article (newest first):
   - title (opens the article) · slug · "Copy link" · publish date
   - checkbox "Indexed in Google" (saved instantly by fetch)
   - one small CELL per article image, numbered 1..N, split at the bottom into F | P halves:
       grey = not posted · F green = posted on Facebook · P green = pinned by hand · P violet = sent in a
       Pinterest bulk upload · whole cell red = marked wrong · dashed/faded = social images not generated yet ·
       small yellow dot = last post older than 30 days (due for a repost)
     hover title = label + how many times posted on each platform and the last dates.
   - under the cells: "Facebook N× · last <date> · Pinterest N× · last <date>".
   - legend at the top, totals, and filters: All · Has cards never posted · Due for a repost · ⚠ Marked wrong ·
     In a bulk upload · Fully posted · Not indexed.
   - buttons: Pinterest bulk upload · Export posting log (CSV) · Templates.
B) CARD PAGE (click a cell): mini navigation of all cells of the article; the Facebook image and the Pinterest
   image side by side, each with "Download"; text boxes with "Copy" and character counts:
     Facebook caption (with hashtags, NO link) · Facebook first comment (contains the article link) ·
     Pin title (≤ 100) · Pin description (≤ 500, never contains the domain) · Tagged topics · Board · Link.
   Buttons "Mark as posted" for Facebook and for Pinterest: each click adds today's date to the platform's log
   (reposts are dated too); "undo" removes the latest date. The list of dates is shown as chips.
   "Mark as wrong" (any role) with a short note → the cell turns red; "Clear" once fixed.
   If the card was in a bulk upload: a violet box with the file name and the scheduled date, and "undo bulk".
   Admin: a form to edit all texts.
C) PINTEREST BULK UPLOAD PAGE: pick pins (chips per article; pins already sent are marked and never selected
   by "auto pick"), a publish DAY (UTC) and a time window (from–to, default 00:00–23:59), a counter, a warning
   that Pinterest accepts about 200 pins a day. The pins are spread evenly across the window.
   Download → CSV with exactly these columns:
     Title, Media URL, Pinterest board, Thumbnail, Description, Link, Publish date, Keywords
   (Media URL = absolute image URL, Link = article URL, Publish date = "YYYY-MM-DD HH:MM:SS" UTC,
   Keywords = tagged topics). After download the cards get pin_bulk_at/date/file and the date is added
   to pin_log (they turn violet). File name pinterest-bulk-<day>.csv.
D) EXPORT CSV (the team's spreadsheet): article, url, indexed, card, style, board, facebook posts, facebook dates,
   pinterest posts, pinterest dates, bulk file, bulk publish date, marked wrong, problem. UTF-8 with BOM (Excel).

E) THE RENDERER (CLI, e.g. tools/social-cards.mjs — Node + Puppeteer, or the project's own image tool):
   node tools/social-cards.mjs <slug> [--force] [--retext] [--template=key]
   node tools/social-cards.mjs --all
   node tools/social-cards.mjs --samples          (one sample per template → the gallery)
   For each article image (1 = hero, then the body images in article order, duplicates skipped): render the FB
   and Pin image in the article's template (HTML/CSS page → screenshot → JPG ~85%), save them to
   /images/social/<slug>-fb-N.jpg and <slug>-pin-N.jpg, and upsert the row with generated texts:
     label = "Hero" / the image alt
     fb_caption: 2–3 short friendly lines about the project (skill level, what makes it nice) + 5–8 hashtags
                 (#crochet #crochetpattern #freecrochetpattern #<type> …), no link
     fb_comment: "Free pattern here 👉 <article URL>"
     pin_title:  keyword-first, ≤ 100 ("Easy Chunky Granny Square Cardigan – Free Crochet Pattern")
     pin_desc:   ≤ 500, keywords naturally (crochet pattern, beginner friendly, yarn weight, hook size), a call
                 to save the pin, no domain
     pin_topics: 5–8 Pinterest topics (Crochet, Crochet Patterns, Amigurumi, Crochet Blanket …)
     pin_board:  by type (Crochet Amigurumi Patterns, Crochet Blankets & Afghans, Crochet Sweaters & Tops,
                 Crochet Bags, Crochet Home Decor, Crochet for Baby, Holiday Crochet, Granny Squares)
   An optional JSON file per article can override the texts. Rows keep texts edited in the dashboard (only empty
   fields are filled) unless --retext. Images that already exist are skipped unless --force.
   Refuse to run if not inside this site's project (check the project config), so it never writes to another site.

gauge, finished size, abbreviations, a full row-by-row / round-by-round pattern copied faithfully from the card
(never invent rounds or stitch counts — ask if something is missing), tips, variations, care instructions, FAQ.
If the site uses schema markup, add HowTo/Article + FAQ. Don't claim AI images are "my photo"; don't invent
testimonials, numbers or awards.

Write this workflow in a file (e.g. PATTERN-PREP.md) in the project so a new AI session can do the job without
